# 03단계: VM

스킬: `kna-03-vm`. `fresh` 모드만. **처음으로 돈이 드는 단계다**(체험 기간에는 무료 크레딧에서 나간다). 인스톨러는
돈이 드는 명령을 하나씩 보여주고 yes 를 기다린다.

이 단계가 끝나면 Google Cloud 에 작은 Linux 서버 한 대가 생긴다. 고정 공인 IP 가 붙고, 웹 포트가 열리고, Docker 가
설치돼 있다. 서버에는 프로젝트 권한이 하나도 없는 전용 서비스 계정 `outline-vm` 이 붙는다. 06단계가 이 서버에서 위키를
띄운다.

## 만들어지는 것

| 리소스 | 이름 | 사양 | 월 USD, 대략 |
|---|---|---|---|
| VM | `kna-wiki-vm` | e2-medium: 공유 vCPU 2개, 4 GB RAM, Debian 12 | 25(us-central1) ~ 31(asia-northeast3) |
| 부팅 디스크 | VM 과 같은 이름 | 30 GB pd-balanced(SSD 기반) | 3 ~ 4 |
| 고정 IP | `kna-wiki-ip` | regional 외부 IPv4 | VM 에 붙어 있으면 약 3.65, 예약만 하고 붙이지 않으면 약 7.30 |
| 방화벽 규칙 | `default-allow-http`, `default-allow-https` | 어디서든 TCP 80, 443 을 `http-server`/`https-server` 태그가 붙은 VM 으로 허용 | 무료 |
| 서비스 계정 | `outline-vm` | VM 의 신원. 프로젝트 역할 없음. 11단계가 backups 버킷 쓰기 권한 하나만 준다 | 무료 |

가격은 리전마다 다르고 바뀐다. 전체 비용은 [구조 문서](../architecture.md#비용)에 있다.

이렇게 고른 이유:

- **e2-medium**: Outline, Postgres, Redis 를 함께 돌리면 메모리가 2 ~ 3 GB 쯤 든다. 1 GB, 2 GB 머신 유형은 업그레이드
  도중 메모리가 모자란다. E2 머신에는 지속 사용 할인이 없으므로 위 가격이 24시간 켜 둔 값이다.
- **고정 IP**: 없으면 VM 을 다시 시작할 때 주소가 바뀔 수 있고, 그러면 DNS 레코드가 엉뚱한 곳을 가리킨다.
- **443 과 함께 80 도 연다**: 위키 앞에 서는 웹 서버 Caddy 가 80번 포트로 Let's Encrypt 에게 이 호스트 이름의 주인임을
  증명하고, 그다음 모든 방문자를 HTTPS 로 보낸다.
- **2 GB swap 과 낮은 swappiness**: 이미지 업그레이드나 DB migration 처럼 메모리가 잠깐 치솟을 때 커널이 프로세스를
  죽이지 않게 하는 여유분이다. 평소에는 swappiness 10 이 RAM 을 우선 쓰게 한다.
- **전용 서비스 계정 `outline-vm`**: VM 안의 프로그램은 metadata 서버에서 VM 서비스 계정의 토큰을 받을 수 있다. 새 개인
  프로젝트의 기본 Compute 서비스 계정(`<번호>-compute@developer.gserviceaccount.com`)에는 프로젝트 Editor 역할이 붙어
  있어서, 그것을 VM 에 붙이면 VM 이 털렸을 때 프로젝트 전체가 위험하다. 그래서 역할이 없는 계정을 새로 만들어 붙이고,
  11단계에서 backups 버킷에 새 덤프를 올리는 권한(`roles/storage.objectCreator`) 하나만 준다. VM 의 access scope 는
  `cloud-platform`(모든 API)이지만, scope 는 상한일 뿐이고 실제 권한은 IAM 역할이 정하므로 역할 없는 계정은 아무것도
  하지 못한다. scope 를 넓게 두면 나중에 권한을 더하거나 뺄 때 VM 을 멈추지 않아도 된다.

SSH(22번)는 기본 네트워크의 `default-allow-ssh` 규칙이 이미 허용한다. 키는 `gcloud compute ssh` 가 관리한다. 같은
네트워크에 딸려 오는 `default-allow-rdp`(3389번, Windows 원격 데스크톱)는 쓸 데가 없으므로 인스톨러가 단계 끝에서 삭제를
제안한다([기본 방화벽 규칙 정리](#기본-방화벽-규칙-정리)).

## 먼저 정하는 것

1. VM 이름. 기본값 `kna-wiki-vm`. 고정 IP 이름은 `kna-wiki-ip`, 서비스 계정 이름은 `outline-vm` 으로 한다.
2. VM 시간대. 로그와 백업 일정에 쓰인다. 기본값은 지금 쓰는 컴퓨터의 시간대다(예: `Asia/Seoul`).
3. 위 비용표에 대한 yes.

## 명령

인스톨러가 프로젝트, region, zone 을 state 에서 읽어 넣는다. 여기서는 예시값으로 적는다.

```bash
# 이전 실행이 남긴 것 찾기. kna-wiki-vm, kna-wiki-ip, outline-vm 이 있으면 새로 만들지 않고 재사용한다
gcloud compute instances list --project=kna-wiki-a1b2 --format="table(name,zone.basename(),status,serviceAccounts[0].email,networkInterfaces[0].accessConfigs[0].natIP)"
gcloud compute addresses list --project=kna-wiki-a1b2 --format="table(name,region.basename(),address,status)"
gcloud iam service-accounts list --project=kna-wiki-a1b2 --format="table(email,disabled)"

# VM 전용 서비스 계정 (무료). 프로젝트 역할은 주지 않는다
gcloud iam service-accounts create outline-vm --project=kna-wiki-a1b2 --display-name="knowanywhere wiki VM (no project roles)"

# 고정 IP (돈이 든다)
gcloud compute addresses create kna-wiki-ip --project=kna-wiki-a1b2 --region=asia-northeast3
gcloud compute addresses describe kna-wiki-ip --project=kna-wiki-a1b2 --region=asia-northeast3 --format="value(address)"
#   203.0.113.10

# 방화벽 (무료. 없는 규칙만 만든다)
gcloud compute firewall-rules list --project=kna-wiki-a1b2 \
  --format="table(name,network.basename(),direction,sourceRanges.list(),allowed[].map().firewall_rule().list(),targetTags.list())"
gcloud compute firewall-rules create default-allow-http --project=kna-wiki-a1b2 --network=default \
  --direction=INGRESS --action=ALLOW --rules=tcp:80 --source-ranges=0.0.0.0/0 --target-tags=http-server
gcloud compute firewall-rules create default-allow-https --project=kna-wiki-a1b2 --network=default \
  --direction=INGRESS --action=ALLOW --rules=tcp:443 --source-ranges=0.0.0.0/0 --target-tags=https-server

# VM (돈이 든다)
gcloud compute instances create kna-wiki-vm --project=kna-wiki-a1b2 --zone=asia-northeast3-a \
  --machine-type=e2-medium \
  --image-family=debian-12 --image-project=debian-cloud \
  --boot-disk-size=30GB --boot-disk-type=pd-balanced \
  --address=203.0.113.10 \
  --tags=http-server,https-server \
  --service-account=outline-vm@kna-wiki-a1b2.iam.gserviceaccount.com \
  --scopes=cloud-platform
```

```
NAME         ZONE               MACHINE_TYPE  INTERNAL_IP  EXTERNAL_IP   STATUS
kna-wiki-vm  asia-northeast3-a  e2-medium     10.178.0.2   203.0.113.10  RUNNING
```

VM 을 만들 때 `Disk size: '30 GB' is larger than image size: '10 GB'` 경고가 함께 나올 수 있다. 무해하다. Debian 12 는
첫 부팅 때 파일시스템을 디스크 크기(30 GB)로 자동 확장한다.

방화벽 규칙 이름은 콘솔의 HTTP/HTTPS 체크박스가 만드는 규칙과 같다. 콘솔에서 이미 체크박스로 만들었다면 목록에
보이고, 인스톨러는 그 규칙을 다시 만들지 않는다. `gcloud compute networks list --project=kna-wiki-a1b2` 에 `default` 네트워크가 없으면 조직 정책이 막았을 수
있다. 인스톨러는 거기서 멈추고 알린다. 네트워크 생성은 이 단계에서 다루지 않는다.

`--service-account` 는 기본 Compute 서비스 계정 대신 방금 만든 `outline-vm` 을 붙인다. `--scopes=cloud-platform` 은 넓어
보이지만 `outline-vm` 에 IAM 역할이 없으므로 VM 이 할 수 있는 일은 늘지 않는다. 11단계가 backups 버킷 권한을 더할 때
VM 을 멈추지 않아도 되게 하려고 지금 넣는다(scope 는 바꾸려면 VM 을 멈춰야 한다). 서비스 계정을 만든 직후라 VM 생성이
`not found` 로 실패하면 30초 뒤 다시 한다. Outline 자체는 06단계에서 만드는 HMAC 키로 uploads 버킷에 접근한다.

## 콘솔에서 직접 만들기

버튼 문구는 콘솔 언어와 시기에 따라 조금 다를 수 있다.

0. **Navigation menu (☰) > IAM & Admin > Service Accounts**(IAM 및 관리자 > 서비스 계정) > **Create service account**
   (서비스 계정 만들기). 이름 `outline-vm`, **Create and continue**(만들고 계속하기). 다음 화면 "Grant this service
   account access to project"(이 서비스 계정에 프로젝트에 대한 액세스 권한 부여)에서는 역할을 **고르지 않고**
   **Continue**(계속), 그다음 **Done**(완료).
1. **Navigation menu (☰) > VPC network > IP addresses**(VPC 네트워크 > IP 주소) > **Reserve external static IP
   address**(외부 고정 IP 주소 예약). 이름 `kna-wiki-ip`, Network Service Tier(네트워크 서비스 등급) **Premium**,
   IP version **IPv4**, Type(유형) **Regional**(리전), 내 region. **Reserve**(예약).
2. **Compute Engine > VM instances > Create instance**(VM 인스턴스 > 인스턴스 만들기).
   - 이름 `kna-wiki-vm`, 내 region 과 zone.
   - Machine configuration(머신 구성): 시리즈 **E2**, 머신 유형 **e2-medium**.
   - OS and storage(OS 및 스토리지): **Change**(변경) > 운영체제 **Debian**, 버전 **Debian GNU/Linux 12 (bookworm)**,
     부팅 디스크 유형 **Balanced persistent disk**(균형 있는 영구 디스크), 크기 **30** GB. **Select**(선택).
   - Networking(네트워킹): **Allow HTTP traffic**, **Allow HTTPS traffic**(HTTP/HTTPS 트래픽 허용)을 체크한다. 방화벽
     규칙 두 개와 태그가 함께 만들어진다. Network interfaces(네트워크 인터페이스) > default > External IPv4 address(외부
     IPv4 주소)에서 `kna-wiki-ip` 를 고른다.
   - Security(보안) > Identity and API access(ID 및 API 액세스): Service account(서비스 계정)에서
     `outline-vm` 을 고르고, Access scopes(액세스 범위)는 **Allow full access to all Cloud APIs**(모든 Cloud API 에 대한
     전체 액세스 허용). 기본값인 Compute Engine default service account 를 그대로 두지 않는다.
   - **Create**(만들기).

그다음 인스톨러로 돌아온다. 인스톨러는 첫 SSH 부터 이어서 한다.

## 첫 SSH

```bash
gcloud compute ssh kna-wiki-vm --project=kna-wiki-a1b2 --zone=asia-northeast3-a --quiet --command='whoami && uname -a'
```

처음 실행하면 gcloud 가 `~/.ssh/google_compute_engine` 에 SSH 키를 만들고 공개 키를 프로젝트에 올린다. `--quiet` 는
passphrase 없이 키를 만든다(인스톨러의 도구 호출은 질문에 답할 수 없다). passphrase 를 걸고 싶으면 인스톨러가 이 명령을
돌리기 전에 내 터미널에서 `gcloud compute ssh kna-wiki-vm --project=kna-wiki-a1b2 --zone=asia-northeast3-a` 를 한 번 직접 실행하고, 물을 때
passphrase 를 넣는다.

`whoami` 가 출력한 사용자 이름은 이 컴퓨터의 사용자 이름에서 온다. 인스톨러는 이것을 `vm.ssh_user` 로 기록한다.
만든 직후에는 VM 이 아직 부팅 중이라 timeout 이 날 수 있다. 1분 기다렸다 다시 한다.

## VM 기본 설정

인스톨러는 아래 명령을 `gcloud compute ssh kna-wiki-vm --project=kna-wiki-a1b2 --zone=asia-northeast3-a --command='...'` 로 VM 에서 하나씩
실행하고 출력을 보여준다.
모두 다시 실행해도 안전하다.

```bash
# 패키지 업데이트
sudo apt-get update && sudo DEBIAN_FRONTEND=noninteractive apt-get -y -o Dpkg::Options::=--force-confold upgrade

# 시간대 (고른 값)
sudo timedatectl set-timezone Asia/Seoul && timedatectl | grep "Time zone"

# 2 GB swap. 이미 있으면 건너뛰고, 재부팅 뒤에도 유지하고, vm.swappiness=10
if ! sudo swapon --show | grep -q /swapfile; then sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile; fi
grep -q "^/swapfile " /etc/fstab || echo "/swapfile none swap sw 0 0" | sudo tee -a /etc/fstab
echo "vm.swappiness=10" | sudo tee /etc/sysctl.d/99-knowanywhere-swap.conf && sudo sysctl -p /etc/sysctl.d/99-knowanywhere-swap.conf

# Docker Engine 과 compose plugin (Docker 공식 설치 스크립트), SSH 사용자를 docker 그룹에 추가
command -v docker >/dev/null || (curl -fsSL https://get.docker.com -o /tmp/get-docker.sh && sudo sh /tmp/get-docker.sh)
sudo usermod -aG docker "$USER"
```

## 기본 방화벽 규칙 정리

Compute Engine API 를 켜면 만들어지는 `default` 네트워크에는 규칙 네 개가 자동으로 딸려 온다.

```bash
gcloud compute firewall-rules list --project=kna-wiki-a1b2 --filter="network~/default$" \
  --format="table(name,direction,sourceRanges.list(),allowed[].map().firewall_rule().list(),targetTags.list())"
```

| 규칙 | 여는 것 | 인스톨러 기본 |
|---|---|---|
| `default-allow-rdp` | tcp:3389, 소스 `0.0.0.0/0` | **삭제를 제안한다.** Windows 원격 데스크톱용이라 Debian VM 에는 쓸 데가 없다. 지우는 일이라 yes 를 받는다 |
| `default-allow-ssh` | tcp:22, 소스 `0.0.0.0/0` | 남긴다. 인스톨러가 03·06·10·11단계에서 `gcloud compute ssh` 로 쓴다. 좁히기는 선택(아래) |
| `default-allow-icmp` | ping | 남긴다 |
| `default-allow-internal` | VPC 내부 대역끼리 | 남긴다 |

```bash
gcloud compute firewall-rules delete default-allow-rdp --project=kna-wiki-a1b2 --quiet
```

`--quiet` 는 gcloud 의 확인 질문을 건너뛴다. 인스톨러는 이 명령을 보여주고 yes 를 받은 뒤에만 실행한다.

### SSH 를 IAP 로 좁히기 (선택)

`default-allow-ssh` 는 키 인증만 받지만 인터넷 전체에 22번을 연다. 더 조이려면 소스를 Google IAP(Identity-Aware Proxy)
의 TCP 전달 대역 `35.235.240.0/20` 으로 좁히고, 내 컴퓨터에서 VM 으로 가는 SSH 를 IAP 터널로 보낸다. 그러면 22번은
Google 을 거쳐 내 Google 계정으로 인증된 연결만 받는다.

좁히면 이후 모든 `gcloud compute ssh`·`gcloud compute scp` 명령에 `--tunnel-through-iap` 를 붙여야 한다. 06·10·11단계의
명령에는 이 플래그가 없으므로, 인스톨러는 11단계까지 마친 뒤 좁히기를 권한다. 설치 중에 좁혔다면 인스톨러에게
명령마다 `--tunnel-through-iap` 를 붙이라고 말한다.

```bash
# IAP API 켜기 (무료)
gcloud services enable iap.googleapis.com --project=kna-wiki-a1b2

# SSH 규칙의 소스를 IAP 대역으로 바꾼다
gcloud compute firewall-rules update default-allow-ssh --project=kna-wiki-a1b2 --source-ranges=35.235.240.0/20

# 이제 SSH 는 IAP 터널로
gcloud compute ssh kna-wiki-vm --project=kna-wiki-a1b2 --zone=asia-northeast3-a --tunnel-through-iap --command='whoami'
```

프로젝트 Owner 가 아닌 계정으로 접속하면 `roles/iap.tunnelResourceAccessor` 역할이 필요하다. 되돌리려면
`gcloud compute firewall-rules update default-allow-ssh --project=kna-wiki-a1b2 --source-ranges=0.0.0.0/0` 을 실행한다.

## 문제 해결

| 메시지 | 원인과 조치 |
|---|---|
| VM 생성 때 `Disk size: '30 GB' is larger than image size: '10 GB'` 경고 | 무해하다. Debian 12 는 첫 부팅 때 파일시스템을 30 GB 로 자동 확장한다 |
| 확인 명령에서 `bash: line 1: swapon: command not found` | `swapon` 이 `/usr/sbin` 에 있어 일반 사용자 PATH 에 없다. `sudo swapon --show` 로 부른다 |
| `Quota 'CPUS' exceeded` 또는 `ZONE_RESOURCE_POOL_EXHAUSTED` | zone 이 꽉 찼거나 체험 계정 할당량에 닿았다. 같은 region 의 `-b` 나 `-c` zone 으로 다시 한다 |
| `The resource ... already exists` | 이전 실행이 만들어 둔 것이다. 인스톨러가 그것을 재사용한다 |
| SSH `Connection timed out` | VM 이 아직 부팅 중이다. 1분 기다린다. 계속되면 `default-allow-ssh` 규칙이 있는지, 소스를 IAP 대역으로 좁혔는데 `--tunnel-through-iap` 를 빼먹지 않았는지 본다 |
| SSH `Permission denied (publickey)` | `gcloud compute config-ssh --project=kna-wiki-a1b2` 를 실행하고 다시 한다 |
| `REMOTE HOST IDENTIFICATION HAS CHANGED` | 같은 IP 로 VM 을 다시 만들었다. `ssh-keygen -R 203.0.113.10` 을 실행하고 `~/.ssh/google_compute_known_hosts` 에서 그 VM 의 `compute.*` 항목을 지운다 |
| 확인 명령에서 `docker: permission denied` | docker 그룹 변경은 새 세션에만 반영된다. 확인 명령을 다시 실행한다(새 세션을 연다) |
| VM 의 서비스 계정이 `...-compute@developer.gserviceaccount.com` 이다 | 콘솔에서 만들 때 기본값을 그대로 두었다. 인스톨러가 VM 을 멈추고 `gcloud compute instances set-service-account kna-wiki-vm --project=kna-wiki-a1b2 --zone=asia-northeast3-a --service-account=outline-vm@kna-wiki-a1b2.iam.gserviceaccount.com --scopes=cloud-platform` 으로 바꾼 뒤 다시 켠다(몇 분 내려간다) |

## 멈추기와 지우기

VM 을 멈추면(`gcloud compute instances stop kna-wiki-vm --project=kna-wiki-a1b2 --zone=asia-northeast3-a`) 컴퓨팅 요금은 멈추지만 위키도
내려가고, 디스크와 IP 요금은 계속 나간다.

VM, IP, 서비스 계정만 지우려면 아래 명령을 쓴다. 디스크의 데이터가 지워진다. 인스톨러는 사용자가 분명히 요청할 때만 명령을
보여준 뒤 실행한다.

```bash
gcloud compute instances delete kna-wiki-vm --project=kna-wiki-a1b2 --zone=asia-northeast3-a
gcloud compute addresses delete kna-wiki-ip --project=kna-wiki-a1b2 --region=asia-northeast3
gcloud iam service-accounts delete outline-vm@kna-wiki-a1b2.iam.gserviceaccount.com --project=kna-wiki-a1b2
```

전부 없애려면 프로젝트를 지운다(`gcloud projects delete kna-wiki-a1b2`). 인스톨러는 이것을 스스로 하지 않는다.

## 체크리스트

- [ ] `kna-wiki-ip` 가 예약돼 있고 VM 의 외부 IP 와 같다.
- [ ] `default-allow-http`, `default-allow-https` 규칙이 있다.
- [ ] `default-allow-rdp` 를 지웠거나, 남기기로 정했다.
- [ ] VM 이 `RUNNING` 이다.
- [ ] VM 의 서비스 계정이 `outline-vm` 이고 scope 가 `cloud-platform` 이며, `outline-vm` 에 프로젝트 역할이 없다.
- [ ] 확인 명령에 `Hello from Docker!`, 2 GB swap, swappiness `10`, 고른 시간대가 나온다.
