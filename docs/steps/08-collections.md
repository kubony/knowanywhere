# 08단계: 콜렉션과 규칙

스킬: `kna-08-collections`. `fresh` 와 `join` 모드 모두. 새 에이전트를 붙일 때(`kna-12-add-agent`)도 다시 돈다.

Outline 에서 콜렉션은 문서를 담는 최상위 폴더다. 이 단계에서 두 종류를 만들고, 에이전트가 따를 규칙을 각 콜렉션의
**설명**(description)에 넣는다. 에이전트는 쓰기 전에 이 설명을 읽는다. 규칙을 바꾸고 싶으면 나중에 위키에서 설명만
고치면 되고, 모든 에이전트가 다음 세션부터 따른다.

| 콜렉션 | 이름 예 | 누가 쓰나 | 무엇을 | 정렬 |
|---|---|---|---|---|
| 에이전트 기록 | `로제 Sessions`, `리사 Sessions` | 그 에이전트만 | 작업 1건당 문서 1개: 배경, 완료 조건, 진행 Update, 완료 기록 | 제목 내림차순(최근 작업이 위) |
| 공유 지식 | `공유 지식`, `Shared Knowledge` | 모든 에이전트와 사람 | 사용자 선호, 프로젝트 요약, 컨벤션, 날짜 있는 결정, 용어집, 머신 목록 | 제목 오름차순(`00 ·`, `10 ·` 번호 순) |

돈은 들지 않는다.

## 이름

- 에이전트 기록 콜렉션은 `<에이전트 이름> Sessions` 다. 에이전트 이름은 00단계에서 정했다. 같은 에이전트를 여러
  머신에서 돌리면 콜렉션은 하나이고, 두 번째 머신은 기존 콜렉션을 그대로 쓴다.
- 공유 콜렉션의 기본 이름은 템플릿 언어가 `ko` 면 `공유 지식`, `en` 이면 `Shared Knowledge` 다. 원하는 이름으로 바꿔도
  된다. 모든 규칙이 이 이름을 가리키므로 처음에 정해 두는 편이 낫다.

## 인스톨러가 하는 일

1. `list_collections` 로 지금 있는 콜렉션을 본다. 이미 있는 콜렉션은 다시 만들지 않는다.
2. 규칙 템플릿에서 설명 본문을 잘라 이름을 채운다. 템플릿은 레포의 `templates/` 에 있다.

   | 템플릿 | 들어가는 곳 |
   |---|---|
   | `templates/collection-sessions.<언어>.md` | `<에이전트> Sessions` 의 설명 |
   | `templates/collection-shared.<언어>.md` 의 개요 부분 | 공유 콜렉션의 설명 |
   | `templates/collection-shared.<언어>.md` 의 시드 문서 부분 | 공유 콜렉션의 첫 문서 `00 · 에이전트가 이 위키를 쓰는 법` (en: `00 · How agents use this wiki`) |

   채운 결과는 `.knowanywhere/render/` 에 파일로 남는다(커밋되지 않는다).
3. MCP `create_collection` 으로 공유 콜렉션을 만들고, `create_document` 로 시드 문서를 만든다.
4. 같은 방법으로 `<에이전트> Sessions` 를 만든다. 이 콜렉션의 첫 문서는 09단계의 스모크 테스트가 쓴다.

## 내가 위키에서 할 일: 권한과 정렬

MCP 로 만든 콜렉션은 만든 사람만 볼 수 있는 비공개 콜렉션이고 정렬은 수동이다. Outline v1.10.1 의 MCP 도구는 이 둘을
바꾸지 못하므로 위키 화면에서 바꾼다. 이번에 새로 만든 콜렉션마다 한다. 위키 화면이 한국어면 괄호 안 이름으로 보인다.

1. `https://wiki.example.com` 을 연다.
2. 왼쪽 사이드바에서 콜렉션 이름에 마우스를 올리면 오른쪽에 `…` 가 나온다. 누른다.
3. **Permissions…**(권한…) 을 누른다. "Share this collection"(컬렉션 공유하기) 창의 **All members**(모든 구성원,
   "Everyone in the workspace") 줄 오른쪽 드롭다운에서 **Can edit**(편집 가능)를 고른다. 창을 닫는다.
4. 다시 `…` > **Sort in sidebar**(사이드바 정렬):
   - `<에이전트> Sessions` 는 **Z-A sort**(내림차순). 문서 제목이 `YYYY-MM-DD · …` 라서 최근 작업이 위로 온다.
   - 공유 콜렉션은 **A-Z sort**(오름차순). 정본 문서가 `00 ·`, `10 ·` 처럼 번호로 시작해서 번호 순이 된다.

"Sessions 콜렉션에는 그 에이전트만 쓴다"는 규칙은 권한이 아닌 설명이 정한다. 에이전트들이 모두 같은 위키 계정으로
접속하므로 권한으로는 구분할 수 없다.

## 확인

인스톨러가 `list_collections` 를 다시 불러 보여준다.

| 항목 | 기대 |
|---|---|
| `permission` | `read_write` (`null` 이면 위의 권한 변경을 아직 안 했다) |
| `sort` | Sessions `{"field":"title","direction":"desc"}`, 공유 `{"field":"title","direction":"asc"}` |
| `description` | 템플릿과 같은 첫 문장과 같은 `## ` 제목들. Outline 이 markdown 을 다시 저장하므로 글자 단위로 같지 않을 수 있다 |
| 공유 콜렉션 문서 | `00 · 에이전트가 이 위키를 쓰는 법` 이 있다 |

위키 화면에서는 콜렉션을 눌렀을 때 맨 위에 규칙이 보이면 된다.

## join 모드에서

- 공유 콜렉션은 이미 있다. 인스톨러는 새로 만들지 않고 설명도 덮지 않으며 id 만 state 에 적는다. 이름을 바꿔 썼다면
  어느 콜렉션인지 묻는다.
- 새 에이전트면 `<이름> Sessions` 를 만든다. 이미 다른 머신에서 쓰던 에이전트면 그 콜렉션의 id 만 적는다.
- 이미 있던 콜렉션의 권한이나 정렬이 위 표와 달라도 실패로 보지 않고 알려 준다.

## 막혔을 때

| 증상 | 원인 | 고치는 법 |
|---|---|---|
| 인스톨러에 `create_collection` 도구가 없다 | MCP 로그인이 읽기 권한만 받았다 | `/mcp` 에서 다시 **Authenticate** 하고 write 를 허용한다 |
| 권한 에러로 콜렉션을 만들지 못한다 | 이 계정에 콜렉션 생성 권한이 없다 | 워크스페이스 관리자에게 확인한다 |
| 사이드바에 새 콜렉션이 안 보인다 | 다른 계정으로 로그인했다. 비공개 콜렉션은 만든 계정에만 보인다 | 에이전트가 연결한 계정으로 로그인하거나, 그 계정에서 권한을 **Can edit** 로 바꾼다 |

## 기록되는 것

```bash
node .claude/skills/kna-status/state.mjs set '{"wiki":{"collections":{"sessions":[{"agent":"로제","name":"로제 Sessions","id":"00000000-0000-4000-8000-000000000001"}],"shared":{"name":"공유 지식","id":"00000000-0000-4000-8000-000000000002"}}}}'
node .claude/skills/kna-status/state.mjs step 08 done
```

`sessions` 는 배열이다. 이 설치가 만들거나 확인한 에이전트마다 한 항목이 있고, 에이전트를 더 붙이면 항목이 늘어난다.
