# 템플릿: `<에이전트> Sessions` 콜렉션 개요 (ko)

`kna-08-collections` 가 이 파일에서 `kna:overview:start` 와 `kna:overview:end` 표시 사이의 본문만 잘라
`{{AGENT_NAME}} Sessions` 콜렉션의 설명(description)으로 넣는다. 넣기 전에 치환하는 자리표시자는 두 개다.

| 자리표시자 | 값 | 예 |
|---|---|---|
| `{{AGENT_NAME}}` | state의 `agent.name` | `로제` |
| `{{SHARED_COLLECTION}}` | 공유 콜렉션 이름 | `공유 지식` |

`<작업 요약>`, `<시각>`, `<머신>` 처럼 꺾쇠로 된 것은 규칙 설명의 일부라 그대로 둔다.
영어판은 `collection-sessions.en.md` 다.

<!-- kna:overview:start -->
이 콜렉션은 **{{AGENT_NAME}}** 의 작업 기록이다. {{AGENT_NAME}} 만 쓴다. 다른 에이전트와 사람은 읽기만 한다.
이 설명이 원본 규정이다. {{AGENT_NAME}} 은 세션마다 첫 쓰기 전에 이 설명을 읽고, 다른 곳의 지침과 다르면 이 설명을 따른다.

## 문서 단위

- **작업 1건당 문서 1개다.** 세션이 바뀌어도, 머신이 바뀌어도 같은 작업이면 새 문서를 만들지 않고 기존 문서를 찾아 이어 쓴다.
- **만들기 전에 검색한다.** 이 콜렉션에서 작업의 핵심어로 검색하고(MCP `list_documents` 에 `query` 와 이 콜렉션의 `collectionId`), 맞는 문서가 없을 때만 만든다. 중복 생성은 금지다.
- **제목**은 `YYYY-MM-DD · <작업 요약>` 이다. 날짜는 작업을 시작한 날의 현지 날짜이고, 작업이 며칠 이어져도 바꾸지 않는다. 이 콜렉션은 제목 내림차순으로 정렬되므로 최근 작업이 위에 온다.
- **icon**: 문서의 `icon` 필드에 주제를 나타내는 이모지 1개를 넣는다. 제목이나 본문에 넣지 않는다.
- **flat 구조**: 하위 문서를 만들지 않는다. 관련 작업은 서로 링크로 잇는다.
- **메인 세션만 쓴다.** 다른 세션이 띄운 서브에이전트나 Worker로 돌고 있으면 이 콜렉션에 쓰지 않고, 자기를 띄운 세션에 결과를 보고한다.

## 본문 골격

```
작성자: {{AGENT_NAME}} · 상태: 🟡 진행 중
시작: 2026-09-15 14:05 KST · 최종 갱신: 2026-09-15 16:40 KST

## 배경
왜 이 작업을 하는지, 무엇이 주어졌는지.

## 완료 조건
무엇이 확인되면 끝인지, 무엇으로 확인하는지(명령, 기대 출력, 수치).

## Update — 2026-09-15 16:40 KST · laptop
한 일, 알게 된 것, 막힌 것, 다음 할 일.

## 완료 기록
결과와 검증 근거.

최종 갱신: {{AGENT_NAME}} · 2026-09-15 16:40 KST
```

- 첫 줄의 `작성자:` 와 상태, 둘째 줄의 시작·최종 갱신 시각, `## 배경`, `## 완료 조건` 은 문서를 만들 때 쓴다.
- `## Update — <시각> · <머신>` 은 의미 있는 진행, 방향 전환, blocker마다 하나씩 붙인다. `<머신>` 은 짧은 호스트 이름(`hostname -s`)이다. 이미 쓴 Update는 고치지 않는다.
- `## 완료 기록` 은 작업이 끝날 때 쓴다. 검증 근거가 없으면 완료 기록이 아니다.
- 마지막 줄 `최종 갱신: {{AGENT_NAME}} · <시각>` 은 쓸 때마다 바꾼다. 시각에는 시간대를 붙인다.

## 상태

| 표시 | 뜻 |
|---|---|
| ⚪ 대기 | 시작 전이거나, 사용자 입력이나 다른 작업을 기다린다. 무엇을 기다리는지 적는다 |
| 🟡 진행 중 | 작업하고 있다 |
| 🔴 차단됨 | 외부 요인으로 진행할 수 없다. 무엇이 막는지와 풀리는 조건을 적는다 |
| ✅ 완료 | 완료 조건을 실제로 확인했고, 그 근거가 `## 완료 기록` 에 있다 |
| ⚫ 취소 | 하지 않기로 했다. 이유를 적는다 |

명령이 exit code 0으로 끝난 것과 목표가 달성된 것은 다른 상태다. 완료 조건을 확인하기 전에는 ✅ 로 바꾸지 않는다.

## 쓰는 시점

- 작업을 시작할 때: 문서를 만들거나, 기존 문서에 재개 Update를 붙이고 상태를 🟡 로 바꾼다.
- 진행 중: 의미 있는 진행, 방향 전환, blocker가 생길 때마다 Update를 붙인다.
- 끝날 때: `## 완료 기록` 을 쓰고 상태와 최종 갱신 줄을 바꾼다.
- 잡담, 단순 질의응답, 가벼운 조회는 기록하지 않아도 된다. 목표가 있거나, 여러 단계를 거치거나, 나중에 누군가 결과를 찾을 작업을 기록한다.

## 증거를 남긴다

수치, 절대경로, 커밋 해시, 실행한 명령과 출력, 링크를 그대로 남긴다. "잘 된다", "개선됐다" 대신 무엇을 어떻게 확인했는지 쓴다. 확인하지 않은 것은 "미검증"이라고 적는다.

## 고칠 때

- **부분 수정을 우선한다.** 문서 전체를 다시 쓰지 않는다. 끝에 붙일 것은 `update_document` 의 `editMode: "append"`, 고칠 곳은 `editMode: "patch"` 로 그 부분만 바꾼다. 전체 교체(`"replace"`)는 서식을 잃을 수 있다.
- 이미 쓴 내용을 고치면(덧붙이기가 아니면) 고친 문단 끝에 `(수정자: <이름> · <시각>)` 을 붙인다. 사용자가 요청해서 고친 경우도 같다.

## 서명이 유일한 저자 표기다

위키 API의 작성자(createdBy)는 로그인 계정이나 API 토큰의 소유자로 기록된다. 여러 에이전트가 같은 계정으로 쓰기 때문에 그 필드로는 누가 썼는지 알 수 없다. 본문의 `작성자:` 줄과 말미 `최종 갱신:` 줄이 유일한 저자 표기이므로 생략하지 않는다.

## 비밀값은 절대 기록하지 않는다

API key, 토큰, 비밀번호, OAuth client secret, 개인 키는 쓰지 않는다. 저장 경로, 변수명, 끝 4자리까지만 쓴다. 예: `/opt/outline/.env` 의 `GOOGLE_CLIENT_SECRET` (끝 4자리 `a1b2`). 명령 출력을 붙이기 전에 비밀값이 섞였는지 먼저 본다.

## 공유 지식은 여기가 아니다

작업 중 알게 된 오래 가는 사실(사용자 선호, 프로젝트 요약, 컨벤션, 결정)은 이 콜렉션에 쌓아 두지 않고 `{{SHARED_COLLECTION}}` 에 정제해서 쓴다. 이 콜렉션의 문서에서는 그 문서를 링크한다.
