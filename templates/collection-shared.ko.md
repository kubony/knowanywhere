# 템플릿: 공유 콜렉션 개요와 시드 문서 (ko)

`kna-08-collections` 가 이 파일을 두 부분으로 잘라 쓴다.

- `kna:overview:start` 와 `kna:overview:end` 사이: 공유 콜렉션(기본 이름 `공유 지식`, 영어판은 `Shared Knowledge`)의 설명(description).
- `kna:seed:start` 와 `kna:seed:end` 사이 ("시드 문서"): 공유 콜렉션에 처음 만드는 문서 `00 · 에이전트가 이 위키를 쓰는 법` 의 본문.

넣기 전에 치환하는 자리표시자:

| 자리표시자 | 값 | 예 |
|---|---|---|
| `{{SHARED_COLLECTION}}` | 공유 콜렉션 이름 | `공유 지식` |
| `{{AGENT_NAME}}` | 시드 문서를 만드는 에이전트(state의 `agent.name`) | `로제` |
| `{{DATE}}` | 시드 문서를 만든 날짜, `YYYY-MM-DD` | `2026-09-15` |

`<에이전트>`, `<날짜>`, `<요지>` 처럼 꺾쇠로 된 것은 규칙 설명의 일부라 그대로 둔다. 이 콜렉션은 모든 에이전트가
쓰므로 개요에는 특정 에이전트 이름을 넣지 않는다. 영어판은 `collection-shared.en.md` 다.

<!-- kna:overview:start -->
이 콜렉션은 이 위키를 쓰는 모든 에이전트와 사람이 함께 읽고 쓰는 공유 지식이다. 한 번 알면 오래 가는 사실을 정제해서 둔다.
이 설명이 원본 규정이다. 이 콜렉션에 쓰기 전에 읽는다. 처음 온 에이전트는 `00 · 에이전트가 이 위키를 쓰는 법` 부터 읽는다.

## 들어가는 것

- **사용자에 대한 사실과 선호**: 호칭, 쓰는 언어, 말투 선호, 작업 습관, 하지 말았으면 하는 것.
- **프로젝트 요약과 현재 상태**: 목적, 레포 위치, 배포 대상, 주로 맡는 에이전트, 현재 상태와 그 상태를 확인한 날짜.
- **컨벤션**: 커밋 메시지, 브랜치, 코드 스타일, 문서와 주석의 언어.
- **날짜 있는 결정**: 무엇을 정했는지, 왜 그렇게 정했는지, 검토한 대안.
- **용어집**: 도메인 용어, 약어, 사람과 서비스의 이름.
- **머신과 환경 목록**: 호스트 이름, OS, 역할, 그 머신에서 도는 에이전트. 비밀값 없이 쓴다.

## 들어가지 않는 것

- **세션 로그와 진행 메모.** 오늘 한 일, 막힌 것, 다음 할 일은 각 에이전트의 `<에이전트> Sessions` 콜렉션에 쓴다.
- **대화 원문(transcript)과 긴 명령 출력 원문.** 필요한 사실만 뽑아서 쓰고 원문이 있는 세션 문서를 링크한다.
- **비밀값.** API key, 토큰, 비밀번호, OAuth client secret, 개인 키는 절대 쓰지 않는다. 저장 경로, 변수명, 끝 4자리까지만 쓴다.

## 누가 쓰는가

- 모든 에이전트와 사람이 쓴다. 에이전트는 메인 세션에서만 쓴다. 서브에이전트나 Worker로 돌고 있으면 쓰지 않고, 자기를 띄운 세션에 보고한다.
- 고칠 때마다 문서 끝에 `수정자: <에이전트> · <YYYY-MM-DD>` 줄을 새로 붙인다. 이전 수정자 줄은 지우지 않는다. 위키의 작성자 필드는 계정 소유자로 찍혀서 누가 고쳤는지 알려 주지 못한다.
- **부분 수정을 우선한다.** 문서 전체를 다시 쓰지 않고 바뀐 부분만 고친다(`update_document` 의 `editMode: "patch"` 나 `"append"`).

## 읽는 법

- 사용자에게 선호, 프로젝트, 컨벤션을 묻기 전에 이 콜렉션을 먼저 검색한다(MCP `list_documents` 에 `query` 와 이 콜렉션의 `collectionId`). 답이 있으면 묻지 않고 그대로 쓴다.
- 답이나 판단에 쓴 문서는 링크로 인용한다.
- 마지막 수정자 줄의 날짜가 오래됐으면 사실이 바뀌었을 수 있다. 중요한 판단 전에는 사용자에게 확인한다.

## 이름 규칙

- **정본**은 두고두고 고쳐 가는 주제 문서다. 제목은 `NN · 주제` 이고, NN은 두 자리 번호다.
  예: `00 · 에이전트가 이 위키를 쓰는 법`, `10 · 사용자 프로필`, `20 · 프로젝트: knowanywhere`, `30 · 컨벤션`, `40 · 용어집`, `50 · 머신과 환경`.
- **결정**은 `YYYY-MM-DD · 결정: <요지>` 로 한 건씩 만든다. 예: `2026-09-15 · 결정: DB 덤프는 30일 보관`.
- 새 문서를 만들기 전에 같은 주제의 정본이 있는지 검색한다. 있으면 그 문서에 더한다. 한 문서는 한 주제만 다룬다.
- flat 구조를 유지한다. 하위 문서를 만들지 않는다.
- 사실마다 출처를 붙인다: 세션 문서 링크, 사용자가 말한 날짜, 커밋 해시.

## 충돌 규칙

- 같은 사실에 대해 내용이 다르면 **날짜가 나중인 쪽이 이긴다**(결정 날짜, 또는 수정자 줄의 날짜).
- **다른 에이전트가 쓴 항목을 지우지 않는다.** 낡은 항목은 ~~취소선~~ 으로 긋고 바로 뒤에 새 내용과 주석을 붙인다. 주석 형식: `(<YYYY-MM-DD> <에이전트>: 바뀐 이유, 근거 링크)`.
- 결정을 뒤집을 때는 옛 결정 문서를 지우지 않는다. 새 결정 문서를 만들고, 옛 문서 맨 위에 `대체됨: <새 문서 링크>` 를 붙인다.
- 어느 쪽이 맞는지 판단이 서지 않으면 고치지 말고 사용자에게 묻는다.

## 시드 문서

제목: `00 · 에이전트가 이 위키를 쓰는 법` · icon: 🧭

<!-- kna:seed:start -->
이 문서는 이 위키에 처음 접속한 에이전트와 사람을 위한 지도다. 세부 규정은 각 콜렉션의 설명(overview)에 있다. 이 문서와 설명이 다르면 설명을 따른다.

## 이 위키는

한 사람을 위해 일하는 여러 AI 에이전트가 기억을 공유하는 곳이다. 예를 들어 맥북·데스크탑·Discord에서 도는 Claude Code "로제", Codex "지수", VM에서 도는 Hermes "제니"가 모두 이 위키를 읽고 쓴다. 같은 이름의 에이전트가 여러 머신에서 돌아도 에이전트는 하나로 본다. 에이전트는 위키의 MCP 서버(`/mcp`)로 접속한다.

## 콜렉션 지도

| 콜렉션 | 누가 쓰나 | 무엇을 |
|---|---|---|
| `<에이전트> Sessions` | 그 에이전트만 | 작업 1건당 문서 1개. 배경, 완료 조건, 진행 Update, 완료 기록 |
| `{{SHARED_COLLECTION}}` | 모두 | 정제된 사실: 사용자 선호, 프로젝트, 컨벤션, 결정, 용어집, 머신 목록 |

## 세션을 시작할 때

1. 자기 `<에이전트> Sessions` 콜렉션의 설명과 `{{SHARED_COLLECTION}}` 의 설명을 읽는다. 세션마다 첫 쓰기 전에 한 번 읽는다.
2. 맡은 일과 관련된 문서를 검색한다. 자기 Sessions에서는 같은 작업의 문서를, `{{SHARED_COLLECTION}}` 에서는 사용자 선호와 프로젝트 정본을 찾는다.
3. 같은 작업의 문서가 있으면 재개 Update를 붙이고, 없으면 `YYYY-MM-DD · <작업 요약>` 으로 새로 만든다.

## 어디에 쓰나

| 알게 된 것 | 쓰는 곳 |
|---|---|
| 오늘 한 일, 막힌 것, 다음 할 일 | 자기 Sessions의 작업 문서 (`## Update — <시각> · <머신>`) |
| 사용자가 밝힌 선호 (예: "커밋 메시지는 한국어로") | `{{SHARED_COLLECTION}}` 의 `10 · 사용자 프로필` 같은 정본 |
| 내린 결정과 이유 | `{{SHARED_COLLECTION}}` 에 `YYYY-MM-DD · 결정: <요지>` |
| 새 머신이나 서비스 | `{{SHARED_COLLECTION}}` 의 `50 · 머신과 환경` (비밀값 없이) |
| 비밀값 | 어디에도 쓰지 않는다. 저장 경로, 변수명, 끝 4자리만 |

## 서명

- Sessions 문서: 첫 줄 `작성자: <에이전트>` 와 상태, 마지막 줄 `최종 갱신: <에이전트> · <시각>`.
- `{{SHARED_COLLECTION}}` 문서: 고칠 때마다 끝에 `수정자: <에이전트> · <날짜>`.
- 모든 에이전트가 같은 계정으로 접속하므로 위키의 작성자 필드로는 누가 썼는지 알 수 없다. 서명이 유일한 저자 표기다.

## 다른 에이전트의 기록

다른 에이전트의 Sessions 문서는 읽고 인용하되 고치지 않는다. 거기서 오류를 찾으면 사용자에게 알리거나, 공유 사실이면 `{{SHARED_COLLECTION}}` 에서 고친다.

## 위키에 닿지 않을 때

MCP 연결이 실패하면(로그인 만료, 위키 다운) 사용자에게 한 줄로 알리고 작업은 계속한다. 쓰려던 Update는 대화에 남겨 두었다가 연결이 돌아오면 쓴다. 설정 파일에서 토큰이나 키를 꺼내 REST API로 우회하지 않는다.

## 에이전트나 머신을 더 붙일 때

설치 레포 knowanywhere 에서 `kna-12-add-agent` 단계를 실행한다. 새 에이전트면 `<이름> Sessions` 콜렉션이 하나 생기고, 같은 에이전트의 새 머신이면 기존 콜렉션을 그대로 쓴다.

수정자: {{AGENT_NAME}} · {{DATE}}
